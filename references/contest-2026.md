# 2026 CST 开发者测试省赛规则与评分

来源为用户提供的《开发者测试赛项说明2026》两页及“开发者测试评分准则”截图。仅在题目适用同一赛制时采用本页。每道题的具体入口、允许修改范围和运行参数以该题实际说明为准。

| 评分项 | 权重 | 处理重点 |
| --- | ---: | --- |
| 分支覆盖率 | 40% | 以实际 JaCoCo 分支计数定位并补齐可达缺口 |
| 变异杀死率 | 30% | 使用项目配置的 PIT 算子，用业务输入和断言检出差异 |
| 可读性与可维护性 | 20% | 补测后独立整理结构、命名、数据、注释与断言 |
| 脚本运行效率 | 10% | 基于重复测时排查慢用例和重复开销 |
| 脚本编写效率 | 0% | 加权成绩同分时按提交时间先后排序 |

- 省赛有两个独立的被测项目，基于 Maven 和 JDK 21，使用 JUnit 5。按题目约定识别实际测试入口，核对所有提交用例都被发现并执行。省赛说明提醒内部类可能影响测试发现。
- 原程序上的 JUnit 用例全部通过是变异计分的前提。出现 `failure` 或 `error` 时无法计算变异得分。
- 赛事允许通过字节码解析和探针分析测试缺口。根据变异工具痕迹让测试失败，或者在运行时改写被测程序以取得原实现得不到的覆盖或杀死记录，均属于赛事禁用做法。
- 不可达路径和等价变异可能使理论上限低于 100%。依据原程序、合法输入和可观察行为论证，保持报告的实际分母和结果。
- 运行效率使用最快满分及中位时间拟合的赛制口径。本地同环境重复耗时用于比较优化，截图给出的信息不足以将本地耗时直接换算为比赛分数。
- 计分首先以该题最后一次提交的 Java 脚本为准。最终复测与报告应对应同一脚本版本。
